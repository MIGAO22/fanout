# fanout

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

把 VPN Gate 的公共节点变成本地 SOCKS5 端口：一个端口一个出口 IP。
再给每个出口挂一个节点链接，客户端连哪个端口就从哪个国家出去。

节点链接有三种管法：同机装了 3x-ui 或 xray-cf-lite 就接管它们的入站，
都没装则 fanout 自己跑 Xray，建站、改站、发链接都在同一个界面里完成。

> **这是 [byJoey/fanout](https://github.com/byJoey/fanout) 的衍生版本。**
> 原始项目、架构设计和全部核心功能都属于
> [@byJoey](https://github.com/byJoey)，本仓库只做了两件事：
> **重写管理界面**和**加固连接层**。
> 上游仍在活跃维护，遇到问题请先看上游，也欢迎直接去
> [byJoey/fanout](https://github.com/byJoey/fanout) 提 issue。

## 这个版本改了什么

### 界面整体重写

原来的界面是单个超长页面，所有信息按功能分区竖着堆下来，出口一多就要一直滚。
现在改成侧栏导航 + 四个视图，前端资源用 `go:embed` 打进二进制，
部署仍然只有一个可执行文件，没有额外的静态目录。

- **默认浅色**，另配一套深色主题，右上角随时切。
- 顶栏下面一排实时胶囊：CPU、内存、交换、存储、负载、TCP、UDP、上行、下行，每 2.5 秒自己走，
  绿条是占用比例，右边是原始量，超过 75% 转黄、90% 转红（口径见下面「使用 → 顶栏负载」）。
  这一排单独占一行、装不下就横滑，手机上也能看到——之前窄屏是整排藏起来的。
- 「设置与连接」里有一张「内置客户端」：卡上只留两份客户端的当前版本，点「检查更新」才报最新版号
  （两份都问 GitHub 官方 release，openvpn 另外问一次本机包管理器和 OpenVPN 官方 apt 源），两份都能就地升级——
  Xray 由 fanout 换二进制，openvpn 走系统包且只点它一个包，本机仓库不够新时才会接一次官方源，
  接了还给一键撤销；apt 和官方源都够不到官方最新时（noble / bookworm 就是这种），
  另外给一条「自己编译 openvpn」：验官方签名、装进独立目录、不覆盖系统那份，也给了撤销按钮
  （口径见下面「使用 → 内置客户端（Xray 与 openvpn）」）。
- 顶部一行 KPI：在线出口（带完成度圆环）、可用节点、覆盖地区、母机 IP、节点链接。
- 批量开出口时下面跟着作业卡片，每条目标的状态单独显示，不用刷整页。
- 出口列表支持卡片 / 表格两种密度，可按「已连通 / 连接中 / 失败」筛，能搜 IP、国家、节点名。
- 每条出口一行讲完一件事：状态色条、国家城市、节点名、出口 IP、槽位、已连通时长、
  SOCKS5 地址（带「鉴权」标记，可一键复制）、挂在上面的协议链接。
  失败时错误原因直接铺在这一行下面，不用点进去找。
- 没绑出口的入站单独列在末尾，附「批量清理」和就地改绑下拉——
  以前它们混在列表里，看不出和 fanout 有没有关系。

### 连接层加固

都是实际跑起来会咬人的问题，不是重构癖：

- **Xray 重载合并**。批量开 N 条出口时，每条 up 都请求重建配置，
  自建模式会连着重启 N 次 Xray，刚连上的客户端被反复打断。
  现在配置仍然同步落盘，只有**重载**进合并窗口（默认 1500 ms，可调），
  失败按指数退避重试。三种后端（3x-ui / 自建 / xray-cf-lite）统一走这条路径。
- **面板调用会自己恢复**。3x-ui 的 API token 失效后原来只能重启 fanout，
  现在遇到 401/403 会重新要一个 token 并重试这一次请求；
  网络类失败只对幂等接口重试，`inbounds/add` 不重试，避免重复建出站。
- **节点列表不再被 hammer**。那份 CSV 有几十 MB，多条隧道同时重连时原来各拉各的。
  现在单飞 + TTL 缓存 + 失败后 45 秒冷却，过期也先拿旧数据顶着。
- **挑节点看的是当下的拥挤程度**。只按 VPN Gate 的 `Speed` 排序会把「没测过速」
  当成最慢，好节点压到最后，而且那列完全不反映此刻有多挤。
  改成速度（饱和曲线）+ 实时会话数 + 延迟三项加权，
  可选 `均衡 / 偏爱速度 / 偏爱空闲 / 偏爱延迟` 四种策略。
- **隧道内拨号有硬超时**。原来是无超时 `net.Dial`，隧道刚掉但 netns 还没拆时
  目标会挂着 SYN 两分多钟，那条客户端连接既不报错也不动，界面上看就是卡住。
  现在 15 秒超时，DNS 查询也一起覆盖。
- **一轮里换过几个节点之后，刚失败的那个降到队尾**，不再每条出口都从头再撞一遍。
- **子进程一律从母机网络命名空间拉起**。这是上游那次
  「Xray 活得好好的、配置校验通过、日志干净，但入站端口在母机上全都看不到」
  事故的同类排查——凡是「在当前命名空间里生效」的命令都必须显式切回去。
  本版本把这条规则补齐到了面板 CLI、服务重启和自更新路径上。
- **数据通道算法按本机 openvpn 的版本喂参数**。同一件事三个版本段三个名字：2.4 叫
  `--ncp-ciphers`，2.5 起改名 `--data-ciphers`（外加 `--data-ciphers-fallback`），2.3 及更早
  两个都没有。喂错名字不是忽略警告，是 `Unrecognized option` 当场退出——原来无条件传
  `--data-ciphers`，在 Ubuntu 20.04 / Debian 10 / CentOS 7 这些还装着 2.4 的机器上
  每条出口都起不来。现在先读本机 `openvpn --version`，按版本段挑名字，读不出来就
  一个都不传、用默认算法表，宁少不多。`fallback` 留 `AES-256-CBC` 是为了那些只讲
  老算法的 VPN Gate 节点：2.6 的客户端默认协商不出 CBC，不加这条会直接握手失败。
- **那份 openvpn 的"版本"和"路径"永远一起解析**。机器上可能同时有两份（系统包一份、fanout 自己
  编的一份装在 `/usr/local/fanout-openvpn/` 下），所以版本探测和 netns 里真正 exec 的那一条都走
  同一个 `openvpnBinary()`——分头查就会写成"读的是 2.7、跑的是 2.6"，症状正好是上一条那个
  `Unrecognized option` 当场退出。
- 上面这些阈值全部进了「设置与连接」，填错会夹回可用区间，不会把自己调死。

### 出口组（本版本新增）

一条节点链接可以绑一组出口，组内按策略选路来保活：单一 / 轮询 / 负载均衡 / 并发。
组上还能打开「掉线自动补新出口」：某条成员长时间连不上就自动挑一条同地区的新出口顶替，
维持你指定的可用条数。详见下面「使用 → 出口组」。

## 原理

每个节点跑在独立的 network namespace 里，netns 内启动官方 openvpn 客户端。
SOCKS5 监听在母机，出站连接用 `setns` 切进对应 netns 建立。

这样做的好处：VPN 的路由劫持只影响自己的 netns，不会切断母机的网络；
多个节点互不干扰，各自一个出口 IP。

```
客户端 ──> 母机 SOCKS5 :随机端口 ──> netns foN ──> openvpn ──> VPN Gate 节点
```

## 安装

需要 root，Linux（依赖 netns）。Windows / macOS 不能跑，只能交叉编译。

### 一行装（预编译，推荐）

```bash
REPO=MIGAO22/fanout bash <(curl -fsSL https://raw.githubusercontent.com/MIGAO22/fanout/main/install.sh)
```

拿的是 [Releases](https://github.com/MIGAO22/fanout/releases/latest) 里由
[release workflow](.github/workflows/release.yml) 构建的
`fanout-linux-amd64.tar.gz` / `fanout-linux-arm64.tar.gz`，机器上不用装 Go。
`REPO=` 必须带——不带时脚本默认去上游 `byJoey/fanout` 找包，装到的是原版界面。

### 从源码装

```bash
git clone https://github.com/MIGAO22/fanout.git
cd fanout
bash install.sh
```

在源码目录里脚本自动改走编译路径（需要 Go 1.21+），仓库名从 `origin` 推断，
不用手动带 `REPO=`。

两条路径的依赖处理一样：openvpn / curl / openssl / iproute / iptables 按发行版自动装，
apt、dnf、yum、pacman、apk、zypper 都认。没装 3x-ui 时还会顺带下载一份
Xray 到 `/var/lib/fanout/bin/`，装了则跳过，入站交给面板管。
服务用 systemd 或 OpenRC 都能装，装完自动开机自启。

> **装完界面还是旧的？** 界面用 `go:embed` 打在二进制里，所以换二进制必须重启服务
> 才生效：`f` → `3) 重启`（或 `f restart`）。`install.sh` 现在重装会显式
> `systemctl restart`——以前用 `enable --now`，对已运行的单元是空操作，
> 于是新二进制在磁盘上、老进程还在服务老界面。
> 想确认手上是哪一份：`fanout -version`，本仓库显示 `v2.0.4`，上游原版是 `v1.3.1`。

> **发新版本。** 推一个 `v*` tag 就会触发 release workflow 出 amd64 / arm64
> 两个包和 checksums；不打 tag 就没有 Release，`releases/latest/download/...`
> 那条地址是 404，一行装会直接失败。

> **自更新指向哪个仓库。** `f update` 和设置里的「更新」卡片默认查上游
> `byJoey/fanout`，直接把上游二进制换上来会静默覆盖掉本仓库的界面改动。
> 上面两条安装路径都不会踩到：release workflow 用
> `-X main.updateRepo=$GITHUB_REPOSITORY`，源码编译则用推断出来的仓库名。
> 自己手动 `go build` 的话，要么加同样的 ldflags，要么用环境变量兜住：
> `FANOUT_UPDATE_REPO=MIGAO22/fanout`。
> 想保持和上游一致、不介意丢掉这些改动，就别设这两个值。

**Alpine** 默认不带 bash，先装一下：

```bash
apk add bash curl
```

另外 fanout 要在 netns 里跑 openvpn，**宿主必须放开 `/dev/net/tun`**。
不少 LXC 小鸡没给这个权限，`ls /dev/net/tun` 不存在且 `mknod` 报
Operation not permitted 的话，这台机器用不了，跟发行版无关。

装完会打印管理界面地址、访问路径和口令：

```
管理界面  http://<你的IP>:8899/gwPuWHvaNr/
访问口令  f81120ac328d11c11b
```

路径和口令都是随机生成的，分别存在 `/var/lib/fanout/basepath` 和
`/var/lib/fanout/password`。路径不对一律返回 404，扫端口的看不到这里跑着什么。

## 使用

界面以**出口**为单位：一行就是一条隧道加上挂在它上面的节点链接。

点「新建出口」，选地区和数量，再选一个已有节点作模板，提交后 fanout 会并行
拉起隧道、为每个出口复制一份节点链接并绑好，进度按目标逐条回报。

地区里还有个「每个国家」：每个有空闲节点的国家各开几条，一次把所有地区铺开。
槽位不够时先开节点多的地区，不会中途报错。

每行右侧两个按钮：换一个节点（出口 IP 变、端口不变，已分发的客户端配置不用改），
或者停掉这个出口。换节点会避开这条出口之前用过的，连点几次每次都是新 IP。

切到「节点链接」视图是全部入站的表格：备注、协议、端口、走哪条出口、状态、详情。
点进详情可以改端口、备注、启停，管理客户端，以及改绑到别的出口。
一个入站可以挂多套客户端凭据，分发给不同的人；每套都能单独重置，
重置后旧链接立即失效。

### 顶栏负载

顶栏那一排胶囊看的是**母机**（跑 fanout 的这台），不是隧道内部，也不是你的客户端。
数字每 2.5 秒自己走一次，鼠标停上去有完整口径。页面上不做任何估算，
所有数值直接来自 `/proc`，所以和 SSH 里看到的能对上：

| 胶囊 | 取数 | 绿条的含义 |
| - | - | - |
| CPU | `/proc/stat` 两次采样的差值，`idle` 含 `iowait` | 这段间隔内的平均占用，全部核心合起来算 |
| 内存 | `/proc/meminfo` 的 `MemTotal - MemAvailable` | 没有 `MemAvailable` 的老内核退回 `MemFree`，会把 cache 算成占用 |
| 交换 | 同上，`SwapTotal - SwapFree` | 没配交换分区时胶囊置灰、显示「无」 |
| 存储 | `statfs` 取**工作目录（默认 `/var/lib/fanout`）所在的分区**，取不到才退回 `/` | 已用 = `blocks - bfree`，百分比分母剔掉 root 预留块，口径和 `df -h` 的 `Use%` 一致；悬停会写明统计的是哪个挂载点 |
| 负载 | `/proc/loadavg` 的 1 分钟值 | 按核心数归一，100% = 可运行任务刚好排满 CPU；悬停看 1/5/15 三个值 |
| TCP | `/proc/net/sockstat` + `sockstat6` 的在用数，**再加 `tw`** | 刻度取临时端口区间宽度，只用来比较多少，不是硬上限 |
| UDP | 同上两张表的 UDP `inuse` | QUIC、DNS 这类流量都算在这里；绑 `[::]` 的双栈监听只出现在 IPv6 那份 |
| 上行 / 下行 | `/proc/net/dev` 两次采样的差值 ÷ 间隔 | 只算默认路由那块网卡，分母是 `/sys/class/net/<网卡>/speed` |

两条设计上的说明：

- **CPU 是差分值**，所以第一次请求要等一个采样窗口（200 ms），
  之后每次的窗口就是轮询间隔。单次读 `/proc/stat` 只能拿到开机以来的累计占用，
  那个数没意义。
- **TCP 里的 `TIME_WAIT` 算进来了**。出口多、客户端连接短的时候，
  `tw` 会比已建立连接多一个数量级——它占的正是临时端口，也就是这台机器
  往外连新目标时最先耗尽的东西。
- **IPv4 与 IPv6 是两张独立的表**，`/proc/net/sockstat` 里只有 AF_INET，
  绑 `[::]` 的双栈监听只出现在 `/proc/net/sockstat6`。两个都读、加起来才是本机总数，
  悬停能看到拆分。只读 IPv4 那份的话，客户端全从 IPv6 进来的机器会把 UDP 显示成一个不动的 0。
- **内核这两行印的是 `inuse`（一个词），老内核印 `in use`（两个词）**，两种都认。
  只按两个词找的话一个都命中不了，UDP 会永远显示 0，而 TCP 因为还能对上 `tw`、
  显示得像个正常数字——这种"错一半"最难查，所以 `/proc/net/sockstat` 的原文形状有单测守着。
- **上行 / 下行是网卡上的量，不是客户端看到的量**：openvpn 的封装开销算在里面，
  走 IPv6 的流量也算在里面（`/proc/net/dev` 不区分协议族）。第一次采样没有前值可减，
  这时显示 `—` 而不是 0，免得把"还不知道"说成"没流量"。

超过 75% 的胶囊转黄、90% 转红。这一排在任何宽度下都不藏东西：宽屏放得下就一行，
放不下就在窄带里折第二行；手机（≤860 px）压成一行可以左右滑。
以前是"窗口不够宽就整排 display:none"，等于在最需要看内存和带宽的设备上把它们藏起来。

节点多了就别一条条复制了。点「订阅」拿一条地址，填进客户端的订阅里，
以后加出口、删出口都会自己跟上。换节点不影响它——端口不变，链接也不变。

地址形如 `http://<服务器IP>:<端口>/<访问路径>/sub?token=<口令>`。
默认出 base64，各家客户端通吃；想看明文在后面加 `&target=links`。
默认只放绑了出口的节点，走直连的不往里混；想全都要就加 `&bound=0`。

订阅要给客户端直接拉，所以这条地址不要登录，**那串 token 就等于密码**，别发群里。
泄露了点「换一串口令」，旧地址立刻失效。

### 内置客户端（Xray 与 openvpn）

「设置与连接 → 内置客户端」把本机这几份客户端的来历和版本一次列清楚，并且只更新该由它更新的：

| 组件 | 装在哪 | 谁负责升级 |
| --- | --- | --- |
| Xray（自建模式） | `/var/lib/fanout/bin/xray` | 这张卡里的「更新到 vX」 |
| openvpn（母机连出口那一跳） | 系统包，`PATH` 里那份 | 这张卡里的「升级 openvpn」，实际执行的就是本机包管理器 |
| 3x-ui / xray-cf-lite 的 Xray | 各自的目录 | 跟着它们自己的面板或脚本 |

先说清楚容易混的两件事。母机连出口用的**不是** Xray，是系统里的 openvpn，跑在 netns 内；
而出口那侧什么都不用装（连的是别人开着的 OpenVPN 服务），所以不存在"更新出口客户端"这回事。
真正被内置进来、又一直没人负责更新的只有 Xray：`install.sh` 的逻辑是「已存在就跳过」，
装它的那天确实是最新版，之后无论重装多少次 fanout 都不会碰它，REALITY、XHTTP 这些
只在新版里才有的东西就会一直缺席。

点「更新到 vX」之后按这个顺序走，任何一步不对都不动真文件：

1. 从 Xray-core 拉本机架构对应的包，解出 `xray`；
2. **先试跑**这份新二进制，确认它在本机起得来、版本号确实是目标版本——下错架构、
   缺动态库这类问题在这里就拦掉，而不是等入站挂了才发现；
3. 用它校验当前正在用的那份配置，新版若不认配置就放弃更新，旧版照常运行；
4. 同目录 `rename` 原子替换，旧版留在 `xray.prev`；
5. 用同一份配置把 Xray 重新拉起。起不来就把 `xray.prev` 放回原位再拉一次，
   宁可不更新，也不会把入站停在半路。

第 5 步会重启一次 Xray，已连上的节点链接会掉一下再自己重连，所以按钮点下去前有确认框。
接管模式（3x-ui / xray-cf-lite）下这张卡只显示版本、不给按钮，并说明那份归谁管——
覆盖别人的运行时，出了问题没人想得起来是这里动的。这份 Xray 的检查更新也**只报数不判新旧**：
显示 `Xray 26.10.21 · 上游 26.11.9`，因为 fanout 不动它，"已是最新"那句轮不到它来说。

openvpn 有**两个"最新版"，胶囊上那个是官方的**。Xray 和 openvpn 的最新版都对接 GitHub 官方
release（`XTLS/Xray-core`、`OpenVPN/openvpn`），tag 的 `v` 前缀会去掉，跟本机 `xray version` /
`openvpn --version` 读出来的号一个写法。之前拿各台机器自己的发行版仓库当基准，才出现"三台机器三个
openvpn 版本、个个都叫最新"——那个号本来就不该被叫作"最新版"。现在三台问出来是同一个：
`openvpn 2.6.14 · 上游 2.7.9`，追平了才说 `· 已是上游最新`。

官方 release 只发源码包（`openvpn-2.7.9.tar.gz` 加一个 `.asc`），装不到机器上，所以按钮上那个号是**问出来的**：
发行版仓库和 OpenVPN 官方 apt 源各问一次，两边取更高的那个，而且必须**严格比本机新**——
一样高或者更旧就不给按钮，否则一次"升级"其实是往回降。问法仍然是先刷一次索引
再读（`apt-get update -qq` / `dnf --refresh list` / `apk update` / `pacman -Sy` / `zypper refresh`，
然后 `apt-cache policy` / `dnf list` / `apk policy` / `pacman -Si` / `zypper info`）——
`apt-cache policy` 看的是磁盘上那份本地索引，几个月不跑 `apt-get update` 时 Candidate 永远等于已装版本。
刷索引最常见的失败是撞锁（`Could not get lock /var/lib/apt/lists/lock ... held by process N`，
自动更新正占着 apt），这种等一下就会自己好，所以撞锁会隔几秒再试一次；还不行就照实写"索引没刷新，
仓库版本号可能偏旧"，不假装查到了。装得到的最高号追不平官方时，卡片下面一行写清这个差
（`这台机器上装得到的最高是 2.7.1；官方 2.7.9 的 apt 源里没有适配本机发行版的包`）——
不写就成了新的"明明有新版却说没有"。

**OpenVPN 官方的二进制仓库只在 deb 上**。形状是（OpenVPN 项目自己的 wiki 页 "OpenVPN software repos"）：

```
deb [arch=amd64|arm64 signed-by=/etc/apt/keyrings/fanout-openvpn-repo-public.asc] \
    https://build.openvpn.net/debian/openvpn/<channel> <codename> main
```

channel 只碰 `release/2.7` 和 `stable`（`testing` 里是 alpha/beta/RC，不算"升级到最新版"）。
fanout 直接读它的 `Packages` 索引比版本，判到确实比本机新才写这台机器：两份文件——
`/etc/apt/keyrings/fanout-openvpn-repo-public.asc`（签名公钥）和
`/etc/apt/sources.list.d/fanout-openvpn.list`（那一行源），然后照常走包管理器。落盘前后都有闸：

- 公钥从 `https://swupdate.openvpn.net/repos/repo-public.gpg` 下来，先核 sha256
  （`1937b44f…45ce710d`，指纹 `30EB F4E7 3CCE 63EE E124 DD27 8E6D A8B4 E158 C569`）；
  对不上就报错退出，已有的钥匙一个字都不动——不能把一份没核对过的钥匙放进 `/etc/apt/keyrings`。
- `signed-by` 只指向这把钥匙，不给它全局信任，机器上其它源的验签不受影响。
- codename / channel / arch 全部白名单校验通过才写文件；写是 `os.WriteFile` 和同目录
  `rename`，不经过 shell。
- 这个源比想象中旧，实测：noble 只到 `2.6.10`、bookworm `2.6.0`、jammy `2.5.7`，
  全都低于 Ubuntu 自己仓库里的 `2.6.19`；resolute 才有 `2.7.1`。所以"接官方源"永远是
  结果比本机新才发生，Debian sid 这类问不到稳定版构建的也只报数不接源。
- 接了就给一条等号的原路退回：卡片上出现「撤销官方源」，删掉 fanout 写的那两份文件并刷一次索引；
  已装好的 openvpn 不动，正在跑的隧道不受影响。留一个第三方 apt 源意味着之后系统包升级会跟着它走，
  这句话写在确认框里，也写在按钮旁边——不只塞在 README 里让人自己找。

非 deb 家族 fanout 只问本机仓库，不会替官方宣布"没有二进制包"：RHEL 系其实有官方的
Fedora Copr（`@OpenVPN/openvpn-release-2.7`，`dnf copr enable` 那条路），fanout 不替你启用它，
但卡片上会把这句说出来，免得把"我的源里没有"讲成"官方没有"。

真按下去之前，确认框里会把**打算在你机器上执行的命令原样摊开**（要接源时连那行 deb 一起）。
家族是读
`/etc/os-release` 的 `ID` / `ID_LIKE` 认家族，再按家族挑工具：

| 家族 | 会执行的命令 |
| --- | --- |
| deb（Debian / Ubuntu） | `apt-get update -qq`，然后 `apt-get install -y --only-upgrade openvpn`；本机仓库不够新时，前面多两步把 OpenVPN 官方 apt 源写进去 |
| rpm（RHEL / CentOS / Rocky / Amazon Linux…） | 有 `dnf` 用 `dnf -y upgrade openvpn`，否则 `yum -y update openvpn` |
| Alpine | `apk update --no-cache`，然后 `apk add --no-cache --upgrade openvpn` |
| Arch | `pacman -Sy --noconfirm openvpn` |
| openSUSE | `zypper --non-interactive refresh`，然后 `zypper --non-interactive update openvpn` |
| 认不出 | 不给按钮，只在卡片下面写一句为什么 |

两点是刻意的。一是除刷索引那步，每条命令**都只点 `openvpn` 这一个包**：一个装客户端的按钮
顺手把整台机器的包升一遍，出的问题没人想得起来是这里动的（这条有单测守着，命令里出现
`upgrade` 而不含包名就红）。二是升级不会打断已经在跑的隧道——替换二进制只是把目录项换掉，
旧进程还挂在原来的 inode 上，所以升完立刻生效的是**新建出口、换节点、重启服务**这些新起的
进程，这句话也写在按钮的确认框和升级完的提示里，免得有人以为隧道会自己重连。

至于 openvpn 的版本为什么要看一眼：2.4 和 2.5 之后连数据通道算法的参数名都不一样，
喂错名字 openvpn 直接退出、一条出口都连不上，fanout 按本机版本挑名字（见上面「连接层加固」）。

**apt 到不了的地方，还有一条源码编译的路。** 官方 apt 源的 `release/2.7` 通道在不少发行版上
只喂到预发布：实测 noble / bookworm / jammy / plucky 是 `2.7~alpha1`，trixie 是 `2.7~beta1`，
questing 是 `2.7~rc1`——数字上比 2.6.19 大，实际比本机那份旧两年，所以 fanout 认 Debian 语义、
见 `~` 就拒（装上它等于一次降级）。稳定版通道又只到 2.6.10 / 2.6.0 这一档。
这种机器想上官方最新只剩自己编，于是「设置与连接 → 内置客户端」多一颗
**「自己编译 openvpn <官方版本号>」**，只在四个条件同时成立时出现：deb 家族、
确实比官方 release 旧、发行版仓库加官方源都够不到那个号、那个号还没编好。
判据全在后端算，前端只看结果，理由和那颗升级按钮一样——藏按钮不等于把关。

确认框会把要发生的事整个摊开（下载哪个 URL、怎么验、apt 装哪几个包、configure 参数、
装去哪个目录、怎么退），因为这一步比升级包重：它要在机器上装编译器。实际动作是

```
下载 https://github.com/OpenVPN/openvpn/releases/download/v2.7.9/openvpn-2.7.9.tar.gz 和它的 .asc
核对 GitHub 在 release 资产上自己报的 sha256
用 OpenVPN 官方主钥匙验签名（F554A3687412CFFEBDEFE0A312F5F7B42F2B01E7）
apt-get update -qq
apt-get install -y --no-install-recommends build-essential pkg-config libssl-dev libcap-ng-dev gnupg
./configure --prefix=/usr/local/fanout-openvpn/2.7.9 --disable-dco --disable-unit-tests
make -j<N> && make install
```

几个决定是有意为之的：

- **装进 `/usr/local/fanout-openvpn/<版本>` 这棵独立的树**，`/usr/sbin/openvpn` 一个字不改。
  fanout 在 `/var/lib/fanout/openvpn/source.json` 里记下"隧道该 exec 哪一个"，
  版本探测和 netns 里那一跳走同一个解析入口——否则会出现"按 2.7 的参数名喂给实际是 2.6 的二进制"。
  胶囊上因此会写成 `openvpn 2.7.9（自编译）`，卡片另起一行说明系统包里那份还是几号。
- **钉的是主钥匙，不是签名子钥匙。** 子钥匙一年一换（v2.6.11 用 `533A6860…`、v2.6.19 用
  `389251C7…`、v2.7.9 用 `33DA8C9E…`，实测三次的 `.asc` 都验证到同一把 2017 年生成的主钥匙）。
  钉子钥匙等于每年让这条路断一次。验签在只装了这把钥匙的独立 `GNUPGHOME` 里做，
  还要求 `VALIDSIG` 行末的主钥匙指纹正好是钉住那把——钥匙服务器给错东西时会直接红。
  主钥匙 2027-02-07 到期，官方换主钥匙时这里要跟着换（`ovpnSrcSigners`）。
- **`--disable-dco`**：DCO 要么靠内核 6.16+ 自带的 `ovpn` 模块，要么装 out-of-tree kmod，
  两条都不该由一个装客户端的按钮顺手引入；顺带也免掉 `libnl-genl-3-dev`
  （`configure.ac` 里它是启用 DCO 时的硬要求）。libcap-ng 则必须装——Linux 上缺它是
  `AC_MSG_ERROR`，configure 当场停，不是警告。
- **只给 deb。** RHEL / Alpine / Arch 的 `pkgconf`、`openssl-devel`、`libcap-ng-devel` 包名各家不同，
  装错一个是白等几分钟，不如让人手动。这条口径和按钮判据写在一起，有单测钉着。
- **任何一步失败都不登记、删掉那棵树**，隧道继续用系统那份；跑完还会核一次
  `openvpn --version` 确实是预期版本号，号不对同样不登记。
- 卡片上有**「撤销源码版」**：删掉那棵树和这条记录，系统那份原地还在，接着的出口回到它。
  已在跑的隧道挂在旧进程上，新建出口、换节点或重启服务之后才换——这句也写在确认框里。
- 自己编的这份**没人跟安全更新**。官方再出新版时这颗按钮会重新出现，这是故意的。

配方本身有一条手动 workflow 钉着：[`openvpn-src.yml`](.github/workflows/openvpn-src.yml)
在 ubuntu-24.04（就是需要它的那档机器）上把"下载 → 核摘要 → 验签 → configure → make → install
→ 自检"整个跑一遍，并确认系统那份没被覆盖、产物认识 `--data-ciphers`。
资产改名、钥匙轮换、依赖变硬要求，都会先在那里红，而不是在用户的 VPS 上红了才知道。

### 只用家宽

VPN Gate 的清单里混着一批它自己的机房服务器（`public-vpn-*` 和
`219.100.37.0/24`），出口一眼看得出是数据中心，还更容易满员。
设置里「只用家宽节点」默认开着，挑节点、地区可用数、自动重连的备选都只看
志愿者家宽。想连机房的一起用就把它关掉。

开关只管新挑的节点，已经跑着的出口不会因为改设置被换掉。

### 出口组：一条链接同时绑几个出口

VPN Gate 的志愿者家宽说掉就掉。一条链接只绑一条出口时，客户端只能跟着遭殃。
「出口组」把几条出口编在一起，入站绑到组上，组内怎么选路由 fanout 负责：

| 策略 | 行为 | 适合 |
| --- | --- | --- |
| 单一出口 | 咬住一条，不通才换组内下一条，换完继续咬住新的 | 想要一个尽量不变的出口 IP |
| 轮询出口 | 每 N 个新目标换一条，循环整组（N 默认 5） | 把流量摊到几条出口上，谁都不容易被限 |
| 负载均衡出口 | 按实测拨号延迟挑最快的，当前这条明显变差就切走 | 在意速度，能接受偶尔换 IP |
| 并发出口 | 同时向组内所有可用出口发起，谁先通用谁 | 只要最快的那一次，愿意多占几路会话 |

轮询和负载均衡**按目标粘性**：同一个站点（不看端口）反复访问始终走同一条出口，
否则刷一个页面就会在同一站点上跳出好几个来源 IP。粘性表有上限，
按最早未使用淘汰，不会被长尾目标撑爆。

几点实现上的选择：

- 每个组是 fanout 自己监听在 `127.0.0.1` 的一个 SOCKS5。Xray 侧看到的仍是
  一个普通 socks 出站，所以 3x-ui / 自建 / xray-cf-lite 三种后端的配置格式一个字都不用改，
  组内换成员也不需要重载 Xray。
- 组员记的是节点主机名，不是槽位号。某条出口自动换了节点，组会跟着改名，
  绑定关系不动。
- 组内一条可用出口都没有时，连接**直接失败**，绝不退回母机直连——
  那样等于把你的真实出口 IP 暴露出去，正是这个工具要避免的事。
- 单条成员的拨号预算是 8 秒（单出口那条是 15 秒）：保活靠的就是快速降级，
  光等第一条就等满 15 秒等于没做。刚失败的成员会进冷却，排到降级队列最后，
  但不会被永久排除——全组都在冷却时照样挨个再试。
- 负载均衡不只看真实流量：没有近期样本的成员会被后台测速补样，
  否则闲一会儿所有样本过期，下一批连接就变成盲选。

#### 掉线自动补新出口

组编辑框里那个开关。打开后组会维持你指定的可用条数：某条成员不行了，
就自动挑一条新出口顶替它的位置，绑在组上的节点链接一个字节都不用改。
关着就是纯手动，组员少一条就是少一条。

判定和补位的规则：

- **等满 5 分钟才算死**。隧道还在、只是没连上时，fanout 自己会换同区节点重连，
  刚掉两分钟的出口大概率回得来，这时候补位是白烧一个槽位、还会和重连抢地区。
  但隧道整个没了（出口被删掉）不等，没有任何东西会把它带回来。
- **新出口跟随掉线那个的地区**。日本那条掉了就补一条日本的，
  组的地区构成不会因为补位悄悄变掉；同地区挑不出空闲节点时才退到任意地区。
- **顶替原位，不重排**。单一模式的默认首选就是成员列表第一条，
  重排等于改了用户的选路起点。
- **先连上才算数**。新出口要真的起了 tun0、状态到 up，才写进组里；
  否则一条起不来的主机会在下一轮又被判成失效，每轮补一条、每轮都失败，
  槽位被垃圾隧道填满。
- **给槽位留水位**。默认留 2 个空槽补不出来的就不补，组上会写明原因
  （「还差 N 条，但槽位只剩 M 个」），而不是把 maxSlots 吃光连带其他出口起不来。
- **试过的死节点冷却 10 分钟**，避免每一轮都挑中同一个连不上的节点反复撞。
- 补位只在后台每 30 秒巡检一次，上一轮没跑完就跳过这一轮：
  补一条最坏要等满整个连接预算，几十秒起步。

补位是这个程序里唯一会「自己开出口」的路径，所以它只在你打开开关时动作，
并且每一条补上来的出口和手动开的完全一样：独立 netns、独立 SOCKS5 端口，
界面上看得见，也能单独停掉。

组只监听回环地址，是 fanout 与本机 Xray 之间的内部件，不对外提供服务；
界面上那个「重置口令」改的就是这一跳。客户端连的仍然是入站端口，不用改配置。

### 节点链接从哪来

同机装了 3x-ui 就直接接管面板里的入站，面板端口、路径、API token 全自动探测，
开了 SSL 也能识别。没装 3x-ui 时 fanout 自己跑一个 Xray，界面上多一个「新建节点」
按钮，可以选协议（VLESS / VMess / Trojan）、传输（TCP / WebSocket / gRPC /
HTTPUpgrade / XHTTP）和安全层（无 / TLS / REALITY）。

REALITY 的密钥对和 shortId 自动生成；TLS 不填证书就生成自签的，分享链接会带上
证书指纹让客户端固定信任。也可以填自己的证书路径。

接管 3x-ui 和自建这两种模式下，改端口、启停、加删客户端、绑定出口的操作完全一致，
用起来没有区别。

装了 [xray-cf-lite](https://github.com/byJoey/xray-cf-lite) 的机器会自动接管它生成的
三个节点。这个模式下节点归 xray-cf-lite 管，fanout 只负责给每个节点指定走哪条出口，
所以界面上不提供新建、删除和改节点的入口——想改端口或 UUID 去 xray-cf-lite 那边改。
两边共用同一份 Xray 配置，fanout 只往里加自己前缀的出站和分流规则，互不覆盖。

后端在设置面板里可以随时切换，本机没装的会置灰并说明原因；也可以用
`-panel 3x-ui` / `-panel native` / `-panel xray-cf-lite` 启动参数固定。
界面里选过之后会记住，重启仍然生效。

## 连接参数

「设置与连接」里可调的东西，以及它们各自在管什么：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| 健康检查间隔 | 10 s | 多久比对一次出口 IP 是否还是建立隧道时那个 |
| 连续失败判定 | 3 次 | 连续几次不符才判掉线，防抖 |
| 探活超时 | 6 s | 单次探测的超时 |
| 重连退避下限 / 上限 | 5 s / 60 s | 自动重连的指数退避区间 |
| 连接预算 | 35 s | 单个节点从拉起 openvpn 到拿到出口 IP 的总预算，超了就换下一个候选 |
| 每轮候选节点数 | 6 | 一轮里最多试几个候选 |
| 面板写入合并 | 1500 ms | Xray 重载的合并窗口，见上文 |
| 节点清单有效期 | 600 s | VPN Gate 那份 CSV 的缓存时长 |
| 挑节点排序 | 均衡 | 均衡 / 偏爱速度 / 偏爱空闲 / 偏爱延迟 |

填 0 或离谱值会夹回可用区间——界面上写错不该让程序退化成「每 0 秒全量重连」这种自伤行为。

## 运维

装完后敲 `f` 打开管理菜单：启停、看日志、查隧道、改端口/口令/访问路径、更新、卸载。

```
  状态      运行中
  版本      fanout v2.0.4
  开机自启  enabled

  管理地址  http://1.2.3.4:8899/gwPuWHvaNr/
  访问口令  f81120ac328d11c11b

   1) 启动          2) 停止
   3) 重启          4) 查看日志
   5) 隧道列表      6) 连接信息
   7) 改端口        8) 改口令
   9) 改访问路径   10) 开机自启开关
  11) 更新         12) 卸载
```

也可以直接带参数用：

```bash
f info       # 连接信息
f list       # 隧道列表
f restart    # 重启
f log        # 跟踪日志
f update     # 从 MIGAO22/fanout 的 Release 更新
f uninstall  # 卸载（服务、二进制、netns 和 /var/lib/fanout 全删）
```

> **界面还是旧的？** 十有八九是老进程还在跑。二进制是单文件、界面用 `go:embed`
> 打在里面的，所以换二进制必须重启服务才生效：`f` → `3) 重启`。
> `install.sh` 现在重装会显式 `systemctl restart`，不再出现「装完没变化」。
> 分清手上是哪一份：`fanout -version`，本仓库构建的显示 `v1.5` 及以上，
> 上游原版显示 `v1.3.1`。

隧道状态存在 `/var/lib/fanout/state.json`，重启后自动恢复，端口保持不变。

健康检查会比对出口 IP 是否还是建立隧道时那个——openvpn 挂掉后 netns 仍能经母机
NAT 出网，只看通不通会漏判。连续几次不符就自动换节点重连，槽位和端口不变，
原先指向它的节点链接会自动改绑过去。

## 本地开发

程序只能在 Linux 上跑（netns + `setns`），Windows / macOS 上只能交叉编译：

```bash
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o fanout .
GOOS=linux GOARCH=amd64 go vet ./...
```

前端在 `web/`（`index.html` / `app.js` / `login.html`），改完重新 build 就会
通过 `go:embed` 带进二进制。想在非 Linux 机器上看界面效果，仓库外的
`preview-server.mjs` 之类静态托管 + 假接口即可，不必真起隧道。

Go 测试需要 Linux 运行时（部分用例依赖 netns），在 Windows / macOS 上
只能 `go vet` 做类型检查，跑不起来：

```bash
# 在 Linux 上执行
go test ./...
```

纯逻辑那批不碰 netns，非 Linux 也能跑，改它们时没必要开虚拟机：

```bash
go test -run 'OvpnSrc|Gpg|OpenvpnCanBuildSource|DebStableVer|DataCipherArgs' ./...
```

`ovpnsrc_test.go` 里钉了 `gpg --with-colons` 和 `--status-fd 1` 的真实输出片段——
钥匙指纹和签名者的解析规则一改就会让验签安静失灵，所以形状必须留档。

## 已知限制

- SOCKS5 支持 CONNECT 和 UDP ASSOCIATE，DNS/QUIC 这类 UDP 也走隧道
  （感谢 [@zsawi](https://github.com/zsawi) 的
  [#22](https://github.com/byJoey/fanout/pull/22)）。域名仍在本机解析。
- 隧道内只有 IPv4，IPv6 目标直接拒绝——放行只会让这条连接绕开隧道暴露真实地址。
- VPN Gate 是志愿者节点，有相当比例已下线或满员（`AUTH_FAILED`）。
  连不上会自动顺着同地区候选往下试，默认最多 6 个。
- 管理界面只有随机路径 + 口令登录，没有 HTTPS。放公网建议前面套一层反代。
  订阅地址同理，token 是明文走的。会话 12 小时自动过期，侧栏底部有「退出登录」，
  它会把本机 token 从会话表里收回——只在浏览器里清 cookie 是不够的，
  被抄走的 token 原本到过期前都还能进门。
- 换节点会避开这条出口之前用过的节点（最多记 16 个），同地区都换过一轮后
  从头开始。一个地区只有一个可用节点时换不动，界面会直接说明原因。
- 出口组的并发策略只对 TCP 生效。UDP ASSOCIATE 那一路「拨号」是在成员里建转发通道，
  抢跑没有意义（谁先连上不代表谁适合跑这路 UDP），会退回按序挑一条。
- 出口组的选路以「一次拨号」为粒度，不做连接级别的字节分流；
  一条已建立的 TCP 从头到尾走同一条出口，中途不会换。
- 自动补齐补上来的是**新节点**，所以那一路的出口 IP 一定变。它保的是「组里始终有
  可用出口」，不是「IP 不变」——在意 IP 稳定就用单一模式、多绑几条组员，别开补齐。
  补位只在打开开关的组里发生，不会碰你没编进组的出口，也不会自己把组扩大。
- 补位挑的是当前 VPN Gate 列表里的空闲节点。列表拉不下来（断网、被墙）时补不了，
  组上会写明「没有可用节点」而不是静默不管。
- 「自己编译 openvpn」只在 deb 家族提供，且编译期间不拦别的 apt 事务：机器上恰好有
  `unattended-upgrades` 在刷索引时，那条 `apt-get update -qq` 会撞锁。撞锁报的是包管理器
  的原话，稍等一下重新点即可——不会留下半截状态（失败即删树、不登记）。
  编出来的那份不过包管理器，`apt list --upgradable` 看不见它，安全更新要靠这里的按钮重新出现；
  不想自己承担这件事就别用它，等发行版仓库喂到稳定版。
- 本仓库的界面截图与交互仍在补充，`README` 里描述的是当前代码的实际行为。
